# ADR: 인증 방식 (Session vs JWT)

## 1. 배경
웹 브라우저 중심 서비스에서 Spring Security 세션(JSESSIONID)과 JWT 중 무엇을 쓸지 결정합니다.

## 2. 비교

### 2.1 JWT
- **장점**: 서버에 상태를 저장하지 않아 수평 확장과 MSA에 유리
- **단점**:
  - 발급한 토큰을 만료 전에 무효화할 수 없음. 막으려면 블랙리스트 저장소가 필요해 결국 세션과 비슷해짐
  - `localStorage`에 두면 XSS로 탈취되고, 쿠키에 두면 CSRF 방어가 따로 필요
  - 요청마다 긴 토큰을 전송

### 2.2 세션
- **장점**:
  - `HttpOnly` 쿠키라 스크립트로 읽을 수 없음
  - 서버에서 세션을 지워 즉시 로그아웃 가능
  - Spring Security가 구현을 제공
- **단점**: 서버 메모리를 사용해 확장이 어려움
  - 해결: Spring Session + Redis로 세션 저장소를 분리

## 3. 결정
**세션 방식을 채택합니다.**
1. 단일 서버에서는 기본 인메모리 세션 사용
2. 서버를 늘릴 때 `spring-session-data-redis` 의존성만 추가해 Redis 세션으로 전환

JWT는 모바일 앱이나 여러 서비스가 서로 인증해야 하는 환경에서 유리합니다. 브라우저 중심인 DASH에서는 보안과 구현 단순성 면에서 세션이 낫습니다.
